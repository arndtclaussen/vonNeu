# RQ (Redis Queue) for time simulation

## Goal: Simulated Time (with a Fast-Forward Feature):

* Concept: Similar to discrete time steps, but the game can be "fast-forwarded" to simulate the passage of time quickly.

* Implementation: Store the current game time and the rate of time passage. When fast-forwarding, calculate the changes that would occur over the simulated time period and update the game state accordingly.

* Pros: Combines the dynamism of a game loop with the ability to skip long periods of inactivity.
* Cons: More complex to implement than a simple game loop, requires careful consideration of how events and actions are handled during fast-forward.

## RQ as part of the solution
We need RQ (or a similar task queue) in the context of time simulation in your game primarily to prevent blocking your main Flask application thread. Here's why:

Responsiveness: Your Flask app handles HTTP requests from clients (web browsers). If your game logic and time simulation run directly within the main thread, any long-running calculations or delays in the game loop would block the processing of these requests. This would lead to a very unresponsive user experience – the UI would freeze, and players wouldn't be able to interact with the game while the simulation is running.

Separate Game Loop: RQ allows you to run your game loop (the update_game_state function) in a completely separate process. This means the game simulation can proceed independently without interfering with Flask's ability to handle HTTP requests. The game loop becomes asynchronous.

Time-Consuming Calculations: Even if your game logic isn't computationally intensive right now, it might become so as you add more features (AI, complex interactions, pathfinding, etc.). By offloading the game loop to RQ, you ensure that your Flask app remains responsive regardless of how complex the game logic becomes.

Scalability: As your game grows, you might want to handle multiple games simultaneously or distribute the game logic across multiple servers. RQ (and especially Celery) makes it easier to scale your game because you can have multiple workers processing tasks from the queue.

In short: RQ enables you to decouple the time simulation from your web application, ensuring responsiveness, scalability, and a smoother player experience.

1. RQ (Redis Queue) with Scheduler:

Concept: Use RQ to manage the continuous time simulation in a separate process. RQ's scheduler allows you to run a task (e.g., update_game_state) at regular intervals. Your fast-forward button can trigger an immediate execution of the same task with a larger time delta.

Implementation (Outline):

RQ Task: Create an RQ task (in controllers/tasks.py) that encapsulates all the logic for advancing game time. This includes updating asteroid positions, and later resource gathering, AI actions, etc. This task should accept a time_delta argument.

# tasks.py (or controllers/gamestate.py)
from rq import Queue
from redis import Redis
from models import db, GameState, Asteroid # ... other models
from controllers.asteroids import update_asteroid_positions
# ... other imports

redis_conn = Redis(host=os.getenv('REDIS_HOST'), port=os.getenv('REDIS_PORT'))
q = Queue(connection=redis_conn)


@q.job
def update_game_state(time_delta_seconds):
    with db.app.context(): # Very important: create an app context
        try:
            gamestate = GameState.query.first()
            if gamestate:
                time_elapsed = timedelta(seconds=time_delta_seconds)
                gamestate.game_time += time_elapsed
                update_asteroid_positions(time_elapsed_seconds=time_delta_seconds)
                # ... (other game updates, e.g. resource changes, AI) ...
                db.session.commit()
                print(f"Game state updated by + {time_delta_seconds} to {gamestate.game_time}")
                return True # Or return useful information.
        except Exception as e:
            db.session.rollback() # Rollback on error
            print(f"Error in game state update: {e}")
            return False # Or raise the exception to RQ
Scheduler: Schedule the update_game_state task to run periodically (e.g., every 5 seconds).

from rq_scheduler import Scheduler
import time
# ... other imports
scheduler = Scheduler(connection=redis_conn)
scheduler.enqueue_in(timedelta(seconds=5), update_game_state, 5)  # Run every 5 seconds, advancing by 5
# Or use cron string (https://apscheduler.readthedocs.io/en/3.x/modules/triggers/cron.html#module-apscheduler.triggers.cron)
scheduler.cron('* * * * *', func=update_game_state, args=[5], repeat=4) # Every minute 4 times advancing by 5

Fast-Forward Button: Keep the existing JavaScript code for the fast-forward button, but modify the Flask route to enqueue the update_game_state task with a larger time_delta argument.

Advantages: Good balance of simplicity and robustness. RQ handles queuing and worker management.
